## 运行方式

需要 Node.js 18 以上（开发环境实测 Node 24）。

```bash
npm install          # 首次运行安装依赖
npm run dev          # 开发模式，默认 http://127.0.0.1:5173
npm run build        # 类型检查 + 打包到 dist/
npm run serve        # 用本地静态服务预览打包产物，默认 http://127.0.0.1:4173
npm run typecheck    # 只做类型检查
npm test             # 运行单元测试（当前 1079 项 / 107 文件）
```

Windows 下可直接双击 `start-demo.cmd`：自动安装依赖、构建并起本地静态服务。

手动操作时，在「系统设置」顶部「手动操作演示」点击「一键载入全链演示数据」，导入后由你自行操作；它不会启动自动演示。小瞳按需补齐为可选项，默认不勾。两种模式分别使用主库与独立自动演示库。

答辩现场在「系统设置」点击「开始完整演示」，系统自动进入独立演示库并完成 23 个阶段：业务闭环、附件与验收、复查、比较、回放、案例、试算、视频、巡检、保养及最终报告，无需逐项手动办理。开发入口：[完整演示](http://127.0.0.1:5173/?workspace=showcase#/settings)；打包服务端口为 4173。
演示中点「自由提问」会等当前提交结束后暂停；回答后点「继续演示／重试」。新流程、六类问法、追问和缺项口径见 [完整自动演示与可问问题](docs/完整自动演示与可问问题.md)。

**必须通过本地静态服务访问，不要直接双击 `dist/index.html`。** 浏览器对 `file://`
协议下的本地数据库有额外限制，业务数据可能无法保存。

## 数据保存在哪里

业务数据与操作日志保存在浏览器 **IndexedDB**：主库 `zhutong-demo`，完整演示库 `zhutong-showcase`（相同表结构、数据分离）。刷新或重开浏览器后仍在；演示身份、偏好、运行进度和回执缓存分别保存。重新演示只复位演示库。
身份与数据模式等少量偏好保存在 `localStorage`。

**清除浏览器数据会丢失全部内容。** 演示前请到「系统设置」页导出 JSON 备份，
在另一台设备上验证恢复结果。切换浏览器或换用户配置目录都会看到另一套数据。

关键业务约定（与方案一致）：

- **缺项不默认为零**：必填项缺失直接拦截，不用 0 或空字符串冒充数据。
- **来源可分辨**：记录来源分「人工录入 / 传感器数据（演示） / CSV 批量导入」；设置页唯一一键入口为四类传感器各补 4 条近 12 分钟的预设采样。近 30 分钟内显眼标「实时传输」并紧邻「演示数据」，过期后退回普通演示来源。数据不来自真实设备，也没有设备心跳。
- **完整自动演示与自由提问**：一键自动准备素材，通过原业务接口完成真实状态流转与附件提交，自动打开实际页面。提问在事务结束后暂停，普通查询与试算不写业务表；刷新恢复为暂停，跨标签只允许一个执行者。见 [新提问流程](docs/完整自动演示与可问问题.md)。
- **到点不等于查完**：任务逐点状态为「待到点 / 已到点，待检查 / 检查完成」，只管到点的操作不会让任务变成"已检查"。
- **谁能操作由仓储说了算**：到点、提交完成、上报巡检问题、关联问题都走受控入口并校验执行角色；异常项必须关联真实问题或写明依据（进操作日志）。
- **照片补传只补缺失**：附件保存草稿标识，重试时先认人再上传 —— 已入库但未关联的只补关联，不会留下重复附件；关联返回值不是成功即按失败处理并保留草稿。
- **问题与任务关联同事务**：巡检问题、任务结果与操作日志在一个 IndexedDB 事务里提交，不产生"问题已建但任务没关联"的半成品。
- **并发提交不出重复**：同一提交标识推出同一主键（`issueIdOf` = 标识的 base64url 编码，不用哈希因此没有碰撞面），并发双击只会复用同一条问题；主键命中时会核对完整提交标识，不一致直接报错；问题编号在事务内分配。
- **写入与留痕同事务**：到点、完成检查、关联问题、提交问题都是"业务数据 + 审计日志"单事务提交，日志失败即整体回滚。
- **写入一律以数据库为准**：任务与问题的校验读库而非读内存快照 —— 并发下"缓存命中但过期"会让系统重复写关联。
- **重复时间不允许静默覆盖**：同一点位同一分钟已有记录时提示改用修订。
- **修改保存原值**：修订会把修订前的数值、单位、采样时间与质量标记完整保留在记录中。
- **有历史记录只归档不删除**：归档保留监测记录、基准版本与操作日志。
- **基准值按版本管理**：修改必须填写原因，历史版本不覆盖，记录保存录入时的基准快照。
- **实测与示例分开标识**：图上用实心/斜线填充区分，表格中用「实测 / 示例」标签。
- **未接入不显示为在线**：设备状态为人工登记，未接入自动心跳前不显示为在线。
- **先判数据质量再判数值**：无效数据、超出设备量程、规则未启用或尚未生效时不参与判定。
- **数据不足不给"正常"**：缺基准或记录不足时显示"数据不足，无法判断"，并说明缺什么。
- **判定等于阈值即命中**：0.60 mm 相对基准 0.50 mm 变化 0.10 mm，判为黄色关注，不做向下取整。
- **恢复不自动关闭**：连续 3 条低于黄色阈值 80% 只标为"恢复待确认"，关闭须由授权人员填写依据。
- **历史记录按当时的基准与规则解释**：基准与规则都按采样时间选取生效版本，变更后旧记录与旧事件的分级不变。
- **同一事件只留一条**：同一点位同一规则在未关闭前只追加证据，等级升高记录升级历史，不重复建单。
- **恢复不自动关闭**：数据回落只把事件标为恢复待确认，关闭须由授权人员填写依据。
- **通知状态分开记录**：已生成、已展示、已确认、已升级分列；未接入真实渠道不写"已送达"。
- **修订替代旧证据**：一条记录在同一事件中最多一条活跃证据，修订后的旧证据移入"已替代证据"保留审计。
- **关闭有权限与时机限制**：只有学校安全管理人员、且事件已进入"恢复待确认"时才可关闭，须填写关闭依据。

## 技术选型

Vue 3 + TypeScript + Vite；状态用 Pinia，路由用 Vue Router（hash 模式），
本地数据库用 Dexie 访问 IndexedDB。界面为自研轻量设计系统，不引入第三方 UI 库；
校园图与楼层图用 SVG 自绘，不引入地图库，坐标以归一化 0–1 保存，
后续要按方案 S12 换成 Leaflet CRS.Simple 时点位数据无需改动。
3D 楼层视图用 Three.js（`three`），**只在切到 3D 时动态加载**，独立分包、不进首屏；
几何全部由本地档案程序化生成（演示示意，非实测图纸或 BIM）。
