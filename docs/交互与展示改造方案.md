# 筑瞳 Demo 交互与展示改造方案

## 1. 目的与边界

本方案服务于 V0.3 的现场演示与学校安全管理人员日常操作。业务规则、权限、事务写入和审计留痕继续沿用既有实现；本轮只改善信息呈现、操作引导和操作后的反馈，不新增绕过业务守卫的快捷入口。

目标是让使用者在每一页都能立即看懂三件事：**当前状态是什么、下一步该做什么、动作完成后留下了什么记录**。

## 2. 代码层审核结论

| 现有能力 | 审核结论 | 需要补的交互 |
| --- | --- | --- |
| 校园地图 | 已支持校园图 → 楼层图 → 测点详情的逐级定位 | 点击测点后应以右侧详情抽屉呈现状态、预警、问题和快捷动作，避免用户在页面上下寻找详情卡片 |
| 巡检任务 | 已有计划、今日待办、我的任务、NFC 核对与清单 | 任务详情为页内展开，长任务会迫使用户滚动；缺少“到点 → 检查 → 异常处理 → 提交”的显式步骤引导 |
| 问题与工单 | 已有筛选、详情、照片、时间线、审核面板 | 列表点击后详情在表格下方展开，问题多时上下文容易丢失；审核前缺少结果预览 |
| 预警中心 | 已有事件详情、证据链、通知和关闭动作 | 需要把“转问题处理”“关联工单”“恢复复测”放进同一处置路径，并显示下一步要求 |
| 操作反馈 | 已广泛使用成功/失败提示与状态标签 | 提示多为页内 notice，容易被滚动带走；操作完成后缺少状态高亮、时间线定位和可继续执行的下一步按钮 |

## 3. 交互改造清单

### I01 统一右侧详情抽屉

**适用页面：** 校园地图、点检巡检、问题与工单、预警中心。

- 列表行、地图点位、任务卡或事件行被点击后，在当前页右侧打开详情抽屉，不跳页、不把详情插入到长列表底部。
- 抽屉宽度建议为 480–560 px；关闭后保留原筛选、滚动位置与选中行。
- 抽屉头部固定显示编号、状态、位置和关闭按钮；底部固定显示当前可执行的主动作。
- 抽屉内动作成功后：更新左侧行的状态标签、短暂高亮该行、在抽屉顶部显示“已写入时间线”的成功条，并提供“查看最新记录”。

**验收：** 打开、关闭、筛选后再打开详情均不丢失列表上下文；动作成功后无需刷新页面即可看到状态变化。

### I02 巡检任务四步引导

**适用页面：** 任务详情抽屉。

在任务标题下增加固定步骤条：

```text
① 到点核对 → ② 填写清单 → ③ 处理异常 → ④ 提交完成
```

- `pending`：高亮“到点核对”；其余步骤置灰。
- `arrived`：高亮“填写清单”；若存在异常项，高亮“处理异常”。
- 异常未关联问题且未填合规依据时，步骤 ③ 显示红色阻塞提示。
- `completed`：四步均完成，展示绿色“检查完成”，并给出“查看关联问题”或“继续下一个测点”。
- NFC 模拟读取点击后给出短暂扫描态；通过、错卡、人工兜底分别用绿、红、橙三种结果条呈现。

**验收：** 用户无需阅读规则说明，也能知道当前被卡在哪一步以及如何继续。

### I03 异常项的就地处置

**适用页面：** 检查清单。

- 选择“异常”时，自动展开该项的处置区；选择“正常”时收起处置区但不丢弃已填写内容，除非用户确认清除。
- 处置区只提供两条明确路径：`上报并关联问题`、`无需建问题`。
- “无需建问题”必须先选原因类型（读数稳定、非结构部位、已当场处理），再填写不少于 10 字说明；已当场处理时建议提供可选照片入口。
- 提交检查完成前显示摘要：必答项完成数、异常项数、关联问题编号或无需建问题依据。

**验收：** 异常项未处置时不能误以为任务可以提交；完成前能看见将写入的处理依据。

### I04 地图测点快捷处置卡

**适用页面：** 校园地图、楼层图。

- 鼠标悬停测点显示轻量信息卡：测点名称、最新读数、当前预警等级、关联开放问题数、设备在线状态。
- 点击测点打开右侧抽屉，提供：`查看趋势`、`查看预警`、`查看问题`、`录入数据`、`发起人工上报`。
- 对存在红橙预警或开放问题的测点使用状态外圈或角标，不只靠测点类型颜色区分。
- 快捷动作只负责导航或打开既有受控表单，所有权限与写入仍由现有仓储入口校验。

**验收：** 从地图定位一个异常测点后，两次点击内可进入趋势、问题或上报动作。

### I05 问题、工单与事件的处置时间线

**适用页面：** 问题详情、预警事件详情、工单详情。

- 使用统一的纵向时间线展示：预警/巡检/人工发现 → 问题提交 → 审核出口 → 工单处理 → 验收 → 复测 → 事件关闭。
- 时间线节点显示操作者、时间、动作、关联编号和证据数量；有照片时可展开缩略图。
- 点击节点可定位到对应的事件证据、问题详情、工单详情或趋势图记录。
- 未完成节点显示为空心状态，并写出下一步要求，例如“待安全管理人员审核”“待维修人员上传完工照片”。

**验收：** 评委在一张时间线上可追溯“发现—处置—验证—关闭”的完整闭环。

### I06 审核与工单的结果预览

**适用页面：** 问题审核抽屉、工单验收抽屉、事件关闭抽屉。

- 选择一级审核出口和二级分类后，在提交按钮上方展示“提交后将发生什么”。
- 示例：`将创建维修工单，问题状态变为处理中，物业维修人员进入待接单。`
- 退回、关闭、无需处理等不可逆或影响待办的动作，使用明确的后果确认文案，而非泛化的“确定/取消”。
- 审核成功后自动切换到最新状态，并在时间线新增并高亮该节点。

**验收：** 用户在点击提交前能理解状态变化、影响对象和下一责任人。

### I07 全局操作反馈与可访问性基础

- 将短时成功/失败提示改为页面右上角统一通知区；重要写入仍在当前详情中保留结果条和时间线节点。
- 所有只用颜色表达的状态同时展示文字，例如“红色紧急核查”“已到点，待检查”。
- 抽屉、弹窗和步骤按钮需支持键盘 Tab 导航、清晰焦点样式、Esc 关闭抽屉；关闭后焦点回到触发它的列表行或地图点位。
- 列表行、测点标记、状态卡片的可点击区域不小于 36×36 px；危险动作使用明确文本。

**验收：** 不依赖颜色或鼠标悬停也能理解主要状态；键盘可完成打开详情、关闭详情和提交主要动作。

## 4. 展示改造清单

### D01 管理人员待办区

在校园总览顶部新增按身份变化的“今日重点”区，不新增业务数据，只聚合已有数据：

| 当前身份 | 卡片 | 主动作 |
| --- | --- | --- |
| 巡检人员 | 待到点、已到点待检查、待补传照片 | 打开我的任务 |
| 学校安全管理人员 | 红橙预警、待审核问题、待验收工单、待关闭事件 | 打开对应筛选结果 |
| 物业维修人员 | 待接单、处理中、被退回工单 | 打开我的工单 |

每张卡显示数量、最紧急的一条简要位置和“查看全部”入口。

### D02 状态色与层级统一

| 状态 | 颜色语义 | 页面文字 |
| --- | --- | --- |
| 待处理 / 待审核 | 黄色 | 待审核、待确认 |
| 已到点待检查 / 需关注 | 橙色 | 已到点，待检查、橙色排查 |
| 紧急 / 逾期 | 红色 | 红色紧急核查、逾期未检 |
| 处理中 | 蓝绿色 | 处理中、已派工 |
| 已完成 / 待复查 | 绿色 | 已检查、待复查、验收通过 |
| 已关闭 / 归档 | 灰色 | 已关闭、已归档 |

状态标签、地图角标、任务步骤条和时间线节点应复用这一套语义。

### D03 演示模式快捷案例

在总览或系统设置保留明确标注的“演示案例”入口，所有案例必须走现有真实仓储路径：

1. 裂缝数据录入 → 黄橙红预警升级；
2. 巡检到点 → 清单异常 → 问题上报；
3. 问题审核 → 工单处理 → 复测恢复 → 授权关闭。

案例运行后显示本次写入的编号清单和“查看闭环时间线”按钮，避免现场临时寻找记录。

## 7. 第四步问题池与审核补充（本轮代码审核）

当前版本已具备人工上报、问题筛选、详情查看和六个一级审核出口，且 350 项自动化测试、类型检查与构建均通过。以下事项来自对审核写入路径和页面交互的复核，需在继续工单闭环前处理。

### P0-1 审核权限必须由仓储层强制校验

当前问题详情页会按身份隐藏审核区，但 `reviewIssue()` 的写入路径尚未在仓储层明确拒绝非“学校安全管理人员”的调用。页面隐藏不构成权限控制：后续新增入口或直接调用 store 时，物业和巡检人员仍可能写入审核结果。

- 在 `reviewIssue()` 进入任何判定和写库前校验当前身份为 `safety`；拒绝时问题、时间线和操作日志均不得变化。
- 审核提交按钮增加提交中状态，事务未返回前禁用重复点击；失败后恢复按钮并保留已填写的审核意见。
- 新增测试：物业、巡检人员审核被拒且数据库不变；安全管理人员审核成功；同一审核动作快速重复提交不产生重复时间线和日志。

**验收：** 任何页面、脚本或未来入口都不能绕过身份校验写入审核结果。

### P0-2 关联已有对象必须真实存在，并形成双向留痕

“关联已有问题/预警事件”当前只需要填写编号。审核时必须在数据库中确认目标存在，关联问题还需排除“关联自身”与无效目标；不能把不存在的编号写进问题档案。

- 关联问题：校验目标问题存在、不是当前问题；建议仅允许关联到未关闭的原问题，除非安全管理人员填写“关联已关闭档案”的专门依据。
- 关联预警：校验事件真实存在；详情中显示事件等级、状态和最近证据，而不是只显示编号。
- 关联成功时在源问题与目标问题（或事件）的时间线同时写入关联节点，并使用同一事务写入，保留两个对象的编号、操作者、时间和审核意见。
- 不删除被关联的问题；源问题保留独立发现记录并进入已关闭或已关联状态，目标问题保留“关联来源”清单。

**验收：** 从任意一端进入详情都可看到另一端；无效编号、关联自身、失效目标均不能提交且不产生半成品数据。

### P1-1 审核出口展示“结果预览”和下一责任人

在审核表单选择一级出口、二级分类后，实时展示状态变化、下一动作和责任人，避免“审核通过”被误解为“问题已经解决”。

| 审核出口 | 提交后预览文案 |
| --- | --- |
| 转维修工单 | 问题进入维修流转；下一步由安全管理人员派工，未创建工单前不得显示“已维修”。 |
| 转专业排查 | 问题进入排查中；下一步补充专业检查结论或转维修决定。 |
| 安排复查 | 问题待复查；显示需复查事项、负责人和目标日期。 |
| 退回补充 | 问题回到待审核；明确要补的照片、位置、描述或测量数据。 |
| 关联既有对象 | 当前问题保留发现记录并关联原问题或预警事件；展示目标对象摘要。 |
| 无需处理并关闭 | 显示关闭依据、审核人和可追溯时间线；不代表关联预警事件自动关闭。 |

**验收：** 提交前能看到“问题将变成什么状态、谁接手、还差什么动作”；提交后新时间线节点自动高亮。

### P1-2 问题池的交互收口

- 顶部状态统计卡改为可点击筛选入口；点击“待审核”即设置筛选条件，再点一次或“重置筛选”恢复全部。
- 列表详情改为右侧抽屉，保持筛选结果和滚动位置；关闭抽屉时焦点回到原列表行。
- 人工上报成功后自动定位并高亮新问题，打开详情抽屉；失败时保留位置、描述和照片草稿。
- 审核出口切换时清空不适用的关联字段（如从“关联已有对象”切到“转维修工单”时清空原问题/事件编号），避免把旧选择带入下一次提交。
- 筛选栏显示“当前匹配 N 条”，并提供一键清除全部筛选；空状态说明下一步可以人工上报或调整筛选。

**验收：** 安全管理人员从问题池筛到待审核问题、完成审核并回看最新时间线不超过三次点击；人工上报后无需重新检索即可查看新建档案。

### P1-3 “无需建问题/无需处理”统一成可统计的处置依据

不要只用“说明不少于 10 字”作为拦截条件。应使用结构化原因加补充说明，统一应用在巡检异常未建问题与审核关闭两个位置：

- 原因必选：`读数稳定`、`非结构部位`、`已当场处理`；补充说明不少于 10 字。
- “已当场处理”建议要求至少一张现场照片或明确说明无法拍照的原因。
- 将原因类型、说明、操作者、楼栋、测点和时间写入时间线与操作日志；统计页按人员、楼栋和原因类型展示频次，便于抽查异常关闭是否集中。

**验收：** 任何“不建单/关闭”都有结构化依据；安全管理人员可查到某人、某楼栋或某类理由的使用次数与原始说明。

## 8. 与第四步后续开发的衔接顺序

1. 先完成 P0-1、P0-2 与对应事务/并发测试；这是审核留痕真实性的前提。
2. 接入预警事件详情“转问题处理”入口，并预填事件、测点、当前等级和证据摘要；仅安全管理人员可提交。
3. 落地 P1-1、P1-2、P1-3，使问题池能稳定完成“发现—审核—分派”的现场展示。
4. 再进入工单闭环：派工、接单、措施、完工照片、验收退回/通过；验收通过只把问题推到待复查，不自动关闭。
5. 最后把 `closeBasis()` 接入事件关闭唯一入口，校验连续 3 条恢复复测，以及“关联工单验收通过”或“安全管理人员无需维修核查结论”。

**现场演示串联：** 地图异常测点 → 人工上报或预警转问题 → 问题池待审核 → 审核结果预览 → 派工与验收 → 复测恢复 → 授权关闭。每一步都从时间线跳转至相邻对象。
