## 三、可复现的演示脚本

### 脚本一：从空白建档并录入（对应方案 V0.1 演示）

1. 打开「系统设置」→「清空并转为空白模式」，填写原因（例如「演示前重置」）→ 确认清空。
   观察：在册楼栋归零，侧栏标签变为「空白建档模式」，日志保留一条清空记录。
2. 进入「建筑与设备」→「新建楼栋」：编号 B01、名称「3号教学楼」、用途、结构形式、建设年份、
   层数、面积、负责人、替补人员、资料来源（任一项留空也可以保存，之后会出现在「档案待补充」）。
   在右侧校园图上点击空白处落位，或拖拽占位框微调 → 保存档案。
3. 在「楼层档案」中「新建楼层」：楼层号填 2。楼层名称与区域清单会自动补全（可手改）→ 保存楼层。
4. 在「测点档案」中「新建测点」：编号自动生成为 `B01-F2-CRACK01`，填名称、区域、类型选「裂缝开合测点」、
   责任人 → 在楼层图上点击落点 → 保存测点。
5. 在测点行点「基准」：填初始基准宽度 0.50、填写变更原因 → 「设置基准」。
6. 到「监测数据」→「录入监测数据」：选测点 → 裂缝宽度填 0.62 → 观察变化量预览显示 Δw = +0.12 mm → 保存记录。
7. **刷新浏览器**（F5），重新进入「校园地图」：档案、图上位置、基准与记录都还在。

### 脚本二：校验与留痕（答辩时用于回应「数据可不可信」）

1. 「录入监测数据」不填宽度直接保存 → 提示「裂缝宽度为必填，缺项不按零处理」，记录不生成。
2. 采样时间选一个晚于当前的时间 → 提示「采样时间晚于当前时间，请核对现场时钟」。
3. 采样时间选成与已有记录同一分钟 → 提示「同一点位该分钟已有记录 R…」，提示改用修订。
4. 在「监测数据」列表点某条记录 → 「修订该记录」：不改原因直接保存 → 提示「修订原因为必填」；
   填写原因并改值 → 保存后记录标记「已修订 1 次」，点开详情可看到修订前的原值、原采样时间和原因。

### 脚本三：归档不删除（答辩时用于回应「数据安全性」）

1. 在「建筑与设备」选 3 号教学楼 → 楼层选二层 → 测点行点「归档」。
2. 不填原因点「确认归档」→ 提示「归档必须填写原因」。
3. 填写原因后确认 → 该测点从默认列表消失；勾选「含已归档」可重新看到，状态为「已归档」。
4. 到「监测数据」按该测点筛选 → **历史记录一条未少**，仍可查询与查看详情。

### 脚本四：备份与恢复

1. 「系统设置」→「导出 JSON 备份」，得到 `zhutong-backup-*.json`。
2. 清空数据后点「导入备份文件」选择该文件 → 数据恢复。
3. 导入前程序会自动把当前数据另存一份备份文件，避免误覆盖。
   导入非本工程的 JSON 会被格式校验拒绝并给出原因。

### 脚本五：CSV 批量导入（正确数据，走正式判定链路）

1. 「监测数据」→ 底部「CSV 批量导入」→「下载模板」，确认提示里的测点编号与类型（取第一个可数值导入的测点，
   人工检查点没有数值字段，不会用来生成模板）。
2. 把模板另存为 CSV，或用「粘贴文本」直接贴入下面这份（测点、时间按现场改）：

   ```csv
   测点编号,采样时间,裂缝宽度,单位,统计窗口,质量标记,备注
   B03-F2-CRACK01,2026-09-20 09:00,0.62,mm,,有效,现场量测
   ```

3. 点「解析并预览」→ 该行状态为「通过」，汇总显示"可导入 1 行"→ 点「确认导入 1 行」。
4. 观察：「导入完成：写入 1 条，跳过错误行 0 条」；「导入结果」区给出本次触发的处置结果
   （例如「事件 E… 追加证据」或「判定结果不构成越限，未生成事件」）。
5. 到记录列表与「预警中心」核对：新记录带基准快照，若越限则事件证据链多一条 —— **导入与手工录入的结果一致**。
6. 来源可分辨：记录列表里该条显示「CSV 批量导入｜历史补录」（手工录入的记录显示「人工录入」）；
   详情页「数据来源」同；「系统设置」操作日志留一条 `CSV 批量导入（文件名）：写入 N 条，跳过错误行 M 条`。
   点该条的「修订」，来源下拉固定为「CSV 批量导入」并提示不可改。

### 脚本六：CSV 导入的六类错误（答辩时用于回应「数据可不可信」）

粘贴下面整段（表头必留），点「解析并预览」，逐行对照提示：

```csv
测点编号,采样时间,裂缝宽度,单位,统计窗口,质量标记,备注
B99-X,2026-09-20 09:00,0.62,mm,,有效,
B03-F2-CRACK01,2026-09-20 09:10,0.62,g,,有效,
B03-F2-CRACK01,2026-09-20 09:20,,mm,,有效,
B03-F2-CRACK01,2026-09-20 09:30,0.62,mm,,有效,
B03-F2-CRACK01,2026-09-20 09:30,0.66,mm,,有效,
```

| 行 | 期望提示 |
| --- | --- |
| 2 | 测点编号 B99-X 在档案中不存在 |
| 3 | 单位「g」不属于该指标，应为 mm |
| 4 | 裂缝宽度为必填，缺项不按零处理 |
| 5 / 6 | 同一份文件里该测点该分钟重复出现，保留第一条即可（第 6 行判错） |

要点：错误行始终只在预览里提示，`payload` 为 `null`，点「确认导入」时不会被写入。
把采样时间改成与已有记录同一分钟，会提示"同一点位该分钟已有记录 R…，请改用修订并保存原值"。

### 脚本七：趋势图上核对历史规则版本

1. 「监测趋势」选 B03-F2-CRACK01、时间范围「近 30 天」。
2. 图上应只有一条数据线 + 一条分段基准线 + 三条阈值线（黄 / 橙 / 红）+ 事件节点（升级处标「事件升级」）。
3. 页脚写明"阈值线 = 该时段生效基准 + 该时段生效规则阈值"，并标注出现过的规则版本（如 V1.0 → V1.1）。
4. 裂缝测点：基准 0.50 mm、阈值 +0.10 / +0.20 / +0.30 mm，三条线应落在 0.60 / 0.70 / 0.80 附近；
   规则换版后黄色阈值改为 +0.12，换版处黄线抬到 0.62 附近并断开。
5. 点任一节点 → 右侧详情给出该记录的基准快照、规则版本、事件编号与通知确认状态。
6. 横轴范围与所选时间范围一致（"近 30 天"即从 30 天前那一刻起到今天）；纵轴刻度为整齐值，
   裂缝测点的三级阈值线应正好落在 0.60 / 0.70 / 0.80 三条刻度上。

### 与 V1.1 §13 的一处口径差异（待确认）

§13.1 写"恢复条件为连续 3 条有效记录低于黄色阈值的 80%"，而 §13.2 的脚本表把"维修后第一天 0.54 mm"标为"恢复待确认"。
按规则条文，单独一条不满足恢复条件。当前实现按**连续 3 条**执行，脚本核对表补齐到第 3 条，页面上注明差异。
若演示需要"一条即恢复待确认"，把规则的恢复条数改为 1 即可（页面可编辑）。

7. ✅ 完工照片、验收退回与验收通过；
8. ✅ 事件关闭接入处置依据：**当前事件关联工单已验收通过** 或安全管理人员填写的"无需维修"现场核查结论（读库复核；
   同测点旧事件工单不能充当依据），
   叠加判定引擎给出的连续 N 条恢复复测与"仅学校安全管理人员"的权限；关闭时事件、关联问题时间线与审计日志同事务写入
   （**事件关闭不改问题状态**：问题仍停在待复查，有自己的审核出口）；
9. 固定 V0.3 答辩链路：红色预警 → 巡检任务 → NFC 到点 → 清单与照片 → 提交问题 → 转维修工单 →
   接单维修 → 完工照片 → 管理验收 → 连续复测恢复 → 授权关闭事件。

已定的口径（不再逐条确认）：

- 编号：`ISS-YYYYMMDD-001` / `WO-YYYYMMDD-001`，本地日期递增，作废不复用；
- NFC：每测点一个活动标签编号，编号一致才算到点；读卡失败可人工输入编号 + 原因，记为"人工兜底签到"；
  编号不一致只生成失败留痕，任务不得标记完成；界面必须写"模拟 NFC 读取"，不构成真实到场证明；
- 照片：本地压缩后存 IndexedDB（每问题 ≤3 张、单条 ≤600 KB、每张约 200 KB），不留原始大图，
  导出时随备份一并带走，导出按钮显示"含照片 N 张，约 X MB"；
- 工单：编号 `WO-YYYYMMDD-001` 在**写事务内**分配；派工限学校安全管理人员且必须指定维修人；
  **验收通过与验收退回限学校安全管理人员**（页面隐藏按钮不算权限，核心状态机同样拦）；
  接单原则上应是被派工人，物业值班可代接但必须写明代接原因；
  验收通过时**工单与关联问题的状态在同一个事务里提交**，通过后问题只进"待复查"，不自动关闭；
- 事件关闭的处置依据：传了事件 ID 时**只认 `order.eventId === 该事件`**，不再按测点回落到旧事件的工单；
  人工上报转出的工单因没有事件标识，不能作为预警事件的关闭依据（改用「转问题处理」或填写"无需维修"核查结论）；
- 演示身份：切换列表为 `DEMO_ROLES`（学校安全管理人员 / 物业值班人员 / 设备管理员 / 巡检人员 / 维修人员），
  **不含「验收人员」**——验收已收口到安全管理人员，该身份在演示中无任何可执行动作；
  角色定义仍保留在 `ROLES`，供历史数据的 `executorRole` 与时间线角色名显示；
- 随时间变化的判定（今日待办、逾期未检、通知超时）**不做自动刷新**：由「刷新状态」与「立即检查超时通知」手动触发，
  避免演示里出现说不清来源的自动变化。
