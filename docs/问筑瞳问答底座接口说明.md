## 二、只读调用入口与时钟纪律

```ts
import { askZhutong, ASK_EXAMPLES } from '@/assistant'

const result = await askZhutong('为什么这条是红色', { context: { eventId: event.id } })
```

- **`askZhutong` 不推进共享时钟**（第二步闸门）：它只读 `clock.nowKey`，不调 `clock.refresh()`。
  一次普通提问既不改数据库，也不改任何界面共享状态（有回归用例守着这两条）。
- **「现在」只由用户显式推进**：界面上的「刷新数据」按钮先调 `clock.refresh()`，再重问上一句。
  实现见 `session.ts` 的 `refresh()`。
- 每次提问都重新取数：本地写入或重新载入后重问，结果随之变化。
- `context.pointId` / `context.eventId` 只在对象仍存在于当前数据集时沿用；**对象消失时返回
  `not_found` 并提示"已不在当前数据集，请重新选择"**，同时清掉失效上下文。
- **数据集被整体替换**（清空 / 重新载入示例 / 导入备份）后，会话会清空上一轮问答并提示
  "数据集已切换…"，避免旧结论与新数据并排显示。

### 结果类型 `AskResult`

| 字段 | 说明 |
| --- | --- |
| `question` / `intent` / `status` | 原问句、意图、状态（见下） |
| `conclusion` | 一句话结论，界面直接展示，不要改写 |
| `facts` | 关键数值：`{ label, value, unit }`，`value` 已按位数取整成字符串 |
| `timing` | 采样时间 / 录入时间 / 是否补录 / 修订次数 / 新鲜度与中文说明（界面按本地时间展示） |
| `provenance` | 来源（人工录入 / CSV / 设备演示补录）、质量标记、测点档案来源、设备健康（人工登记口径） |
| `evidence` | 证据编号：记录号或事件号 + 内部主键 + 说明 |
| `candidates` | 消歧候选 `{ id, label, detail }`，仅在 `status === 'need_choice'` 时非空 |
| `gaps` | **空态说明**：缺什么、为什么不能给结论。界面必须展示，不得折叠 |
| `links` | 只读导航（见第四节），`path` + `query` 已生成好 |
| `pendingCommands` | 需人工确认的指令；仅明确的红色演示请求返回 `enabled: true`，表示可以打开确认弹窗，不表示提问已执行 |
| `dataNotes` | 数据口径提示（人工登记、演示补录、无心跳等），界面必须原样展示 |
| `computedAt` | 本回答依据的"现在"刻度（来自共享时钟） |

### 状态语义（界面据此选空态）

| `status` | 含义 | 界面 |
| --- | --- | --- |
| `answered` | 给出了有数据支撑的结论 | 正常渲染 |
| `need_choice` | 命中多个（同名测点、多条红色事件等） | 渲染候选按钮，点选后带 id 重问 |
| `not_found` | 对象不在当前数据集，或没有可用于下结论的数据 | 空态 + `gaps`；**不要显示"正常"** |
| `unsupported` | 认得出但不支持（影像未接入、写入指令、没认出的问法） | `gaps` 里的说明与可问示例 |
| `awaiting_confirmation` | 已识别受支持的红色演示请求，尚未写库 | 展示影响范围与「核对并准备」按钮 |

### 意图与消歧（确定性，无模型）

意图：`campus_overview` / `point_status` / `event_reason` / `open_events` / `media_compare` / `demo_command` / `unknown`。
分类顺序固定：明确的演示指令 → 影像 → 全校 → 概况弱词 → 追因 → 未处置队列 → 单测点 → 指代追问（`它怎么样` 这类只沿用上下文）。

消歧：测点编号精确匹配优先（大小写不敏感、回显用户原写法）→ 按楼栋 / 指标缩小范围 →
名称特征取**最长公共子串得分最高的一组**（避免把"一层主馆区人工检查点"拉进"一层走廊人工检查点"的候选）→
命中多个返回候选（**不替人猜**）→ 一个都没命中就说明是哪一栋楼 / 哪个编号没有 →
**一句线索都没有时不把全部测点当候选**。
候选或上下文里已经由人明确选定的对象，下一轮不再重新弹候选。

## 三、口径纪律（写进回答，不许绕过）

| 场景 | 口径 |
| --- | --- |
| 同测点多条记录 | 只取 `quality === 'valid'` 的**最新有效**记录；比它更新那条若不有效，明确写出"已跳过"及其质量标记 |
| 采样时间 vs 录入时间 | 两个字段分列，统一按本地时间展示；补录写明"历史补录，不代表实时上报" |
| 记录被改过 | `revision > 0` 时写明"已被修订 N 次，当前值为修订后数值" |
| 读数偏旧 | 只说"数据偏旧"，并说明**本机没有设备心跳，不能判断设备离线** |
| 设备健康状态 | 一律标"人工登记"；未接入的设备写"无设备心跳" |
| 没有有效读数 | `not_found` + 缺什么；**不显示"正常"** |
| 没有适用规则 / 没有关联事件 | 分别明说，不省略 |
| 事件触发原因 | 只引用事件里已落库的判定快照：触发值 / 基准值 / 阈值 / 规则与版本 / **证据记录号**；判定说明直接用引擎写下的 `reason`，助手不再自己算一遍变化量 |
| 来源为 `device` 的记录 | 写明它是"演示链路写入的补录数据，不是已接入的设备心跳" |
| 风险等级 | 一律引用判定引擎生成的事件，**助手不重算阈值** |
| 防重复计数 | 未关闭事件按事件 ID 去重：升级只改同一条事件 |

## 四、导航白名单（只读）

界面用 `result.links` 直接 `router.push({ path, query })`，**不要自己拼路由字符串**；
未登记的动作由 `buildLink()` 直接抛错（方案 B1：禁用任意命令执行）。

| `kind` | 链接 | `deep` | 状态 |
| --- | --- | --- | --- |
| `event_detail` | `/alarms?event=<事件ID>` | ✅ | 现有参数 |
| `event_report` | `/reports/event/<事件ID>` | ✅ | 现有路由 |
| `alarm_queue` | `/alarms?scope=unclosed` | ✅ | 现有参数 |
| `issue_detail` | `/issues?issue=<问题ID>` | ✅ | 现有参数 |
| `point_building` | `/campus?b=<楼栋ID>` | ✅ | 定位到楼栋；测点需在楼层图上再点一次 |
| `point_trend` | `/trend?point=<测点ID>` | ✅ | **第二步补齐**：进页即选中该测点 |
| `media_page` | `/media?point=<测点ID>` | ✅ | **影像联动补齐**：进页即选中该测点的会话影像 |
| `workorder_detail` | `/issues?workOrder=<工单ID>` | ✅ | **第二步补齐**：展开所属问题并高亮该工单 |
| `overview` / `campus_map` / `monitor` / `reports` | 对应页面 | — | 页面级入口 |

对象直达的**无效 ID 空态**：`/trend?point=<不存在>` → "深链里的测点打不开" + 原因；
`/issues?workOrder=<不存在>` → 页面顶部提示"找不到工单 …，下表仍是全部问题"。
解析规则在 `src/assistant/deepLink.ts`，视图只负责渲染。注意 `?workOrder=open` 是**旧的筛选值**，
不会被当成工单 ID。

### 写入指令（需要明确确认）

```ts
import { pendingCommands } from '@/assistant'
pendingCommands()     // 默认关闭，供不支持的写入请求说明
pendingCommands(true) // 仅明确的红色预警演示请求：可打开确认弹窗
```

`askZhutong()` 仍只读：提问不会写库。界面先展示「核对并准备」，再由独立弹窗说明最多 4 条历史记录、红色待确认事件、冲突拒绝与不预建问题/工单；
只有点击「确认准备」才调用 `executeConfirmedCommand()`，它只允许 `prepare_red_demo` 并复用 `useDemoScenarioStore().load('liveResponse')`。
取消、Esc 与其它指令不写库；成功后先关闭问答面板、展示红色强提醒，点提醒里的「查看并处置」再定位事件详情。
重复准备按既有场景幂等跳过记录并重放提醒。
这条指令始终使用固定演示测点；问句中另指定楼栋或测点时不展示可执行按钮，避免把“要 1 号楼”误执行成 3 号楼。

## 五、界面约定（已实现）

- 桌面端从右侧展开、约占 50% 视宽（`min(50vw, 720px)`，最小 420px），**左侧页面仍可查看和操作**；
  约 900 px 以下改全屏。层级 `z-index: 50`：**刻意压在弹窗（60）与抽屉（55）之下**，
  红色预警弹窗出现时完整盖住面板。
- Esc 关闭：焦点在面板内时总是生效；全屏形态下整页生效。关闭后由壳层把焦点还给顶栏入口按钮。
- 候选点选：`need_choice` 渲染候选按钮，点选后带 `objectId` 重问。
- 从测点卡 / 事件详情点「问小瞳」即带上上下文并立刻问一句默认问法
  （测点 `它怎么样`，事件 `为什么这条是红色`）。
- **入口是悬浮小瞳**（不是顶栏按钮）：尺寸 80 px，默认落在**左下角**（避开右侧「楼栋档案」正文与地图缩放控件）；
  **轻点打开面板、拖动不会误打开**（位移阈值桌面 6 px、窄屏 12 px）；**松手后靠边停靠**（贴向更近的左右一侧）；
  位置存本机偏好，窗口变化后自动夹回可见区域；
  键盘可操作（Tab 聚焦、Enter/Space 显式激活、方向键微调、Shift 加速）。
  交互口径参考 `hnuahe_yingxin-main` 的 `useDrag`，**未照搬**其遮罩、联网问答、语音播报与"AI 在线"文案。
- **动效分层**（这是"入口有生命感"的关键）：`float`（缓慢上下浮动 ±4 px）**常驻不停**，
  状态只叠加自己的层 —— `halo` 柔和呼吸光环、`orbit` 慢速外圈常驻旋转；
  `searching` 期间 `scan` 扫描环持续运转并点亮镜头高光；`found` 时 `spark` 闪一下 + 点头一次，
  **浮动层不受影响**，所以反馈之后入口仍在动；`empty` 整体压暗、光环收敛。
  旧实现把 `found` 的一次性动画直接写在形象本体上，播完就彻底静止 —— 这是本轮修掉的问题。
  回答卡片里的小头像用 `quiet` 模式：只做静态展示，不参与动效。
- 小瞳四态：待机 `idle`、检索中 `searching`、找到证据 `found`、无数据 `empty`；
  `data-paused="true"` 时暂停装饰动画（**拖动中**与**红色预警弹窗出现时**由父级设置）；
  **入口状态会回落**：`entryState` 只在 `searching` 期间持续，`found`/`empty` 亮 `ENTRY_BURST_MS`（2600 ms）
  之后回到 `idle` —— 语义状态仍留在面板头部与回答卡片（`mascotState`），不受回落影响。
- 跟随系统"减少动态效果"：停用位移与旋转，保留光环/轨道的静态可见性，状态改由颜色与文字承载
  （入口上的状态标签在非待机态直接显示）。
- 统一形象用 `xiaotong.png`（悬浮入口 68 px 内层、面板头部 56 px、回答头像 26 px 同一张图、同一套状态）。
- 层级：悬浮入口 `z-index: 45` < 面板 50 < 抽屉 55 < 弹窗 60 —— **红色预警弹窗永远在小瞳之上**，
  且弹窗期间小瞳的装饰动画暂停。
- 「刷新数据」是唯一推进"现在"的入口；面板上的提示会写明"已按当前时刻重新读取数据"。

## 六、影像联动（工作线 C 的展示页 + 问答）

- 页面：`/media`（`src/views/media/MediaView.vue` + `src/components/media/`），导航「影像对比」。
- 会话影像：`src/stores/media.ts`（Pinia，**只存内存**）；影像页可点「一键加入前后照片」载入随包的两张同机位生成素材，也可点「一键加入参考图」载入 CC0 公开实拍图；两类均不依赖摄像头、文件选择框或外网。
  领域类型在 `src/types/media.ts`（`MediaFrame` / `MediaFrameRef` / `frameOriginLabel`）；
  采集工具在 `src/core/media/capture.ts`（压缩、亮度提取、视频抽帧）；
  比对判定在 `src/core/media/compare.ts`（**纯函数**，含 15 项用例）。
- 问答读的是只读投影 `snapshot.media`：`{ frames: MediaFrameRef[]; compare: MediaCompareRecord | null; videoLoaded: boolean }`，
  **不把 Blob 带进回答层**；问答侧选影像的规则是"问句点名的测点优先，否则用会话里影像最多的测点"，
  并把定位口径写进 `dataNotes`。

### 口径硬约束（界面与问答共用一套话术，`src/types/media.ts` 与 `src/assistant/answers/media.ts`）

## 七、尚未实现 / 不做的事（如实标注）

- 不接外部 AI API，不做自然语言生成；回答全部来自固定模板。
- 不做本机摄像头采集；根据最新演示口径，影像页不请求任何摄像头或真实器械权限。
- 视频支持回放/抽帧/差异/关系/可比条件等固定自然语言问法；不做逐帧识别，只抽 3 帧做区域统计。
- 影像不做持久化：不新增影像表、不做数据库迁移，刷新即失。
- 普通提问不写库；临时数据只从设置页唯一全链按钮启动授权，明确任务的按需补齐复用原准备队列。旧独立确认弹窗已撤下。
- 不推断设备真实在线、不输出真实心跳、不代替人工确认。
- 「减少动态效果」只按 CSS 媒体查询实现，浏览器自动化运行时未提供媒体特性模拟，**未经实机模拟验证**。
- 悬浮入口的 Enter / Space 激活**显式处理 keydown**（不依赖浏览器"按键 → 合成 click"的默认动作），
  并带 400 ms 去重窗口，避免真实浏览器里"keydown + 合成 click"开两次；去重逻辑本身未在真机验证。
