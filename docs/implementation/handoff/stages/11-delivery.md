# 阶段 11：综合验收、离线交付与比赛准备

目标：在另一干净环境按说明部署并完成五条固定路径，确认数据库、媒体、知识、模型和移动端可恢复、可离线运行。
前置：阶段 4—10 均通过，关键接口/知识/问集/场景版本冻结。
冻结后仅修复缺陷；新增需求应单列变更和回归范围，不把竞赛验收扩成长期平台开发。

## 实施步骤

### 11.1 冻结与需求追踪

- 形成阶段验收编号→代码提交→测试→真实证据→交付文件的映射。
- 冻结 Git 提交、Alembic head、Python/Node/Flutter 依赖、镜像摘要、模型/索引和场景版本。
- 盘点所有按钮/菜单/助手预设/自动步骤，列出停用或尚未接入项，不能留下“能点但写假数据”入口。
- 核对固定限制：无登录密码、演示身份、模拟 NFC、演示阈值、本地 AI 与无外部通知。

### 11.2 自动验证与结构复核

- 后端全量单元/集成测试、覆盖率至少 80%，关键状态、权限、事务和幂等错误分支逐项有证据。
- Web 全量测试、启动器测试、类型检查和生产构建，关键 UI 路径回归。
- Flutter analyze/test/构建和真机回归，升级安装保留本地草稿/队列，原数据不被无提示清除。
- Python/JS/TS/Vue/Dart 文件规模、函数、参数、目录层级及新增重复逻辑/隐藏耦合检查。
- 空库升级、真实旧备份升级、失败回滚/恢复；不以修改历史迁移让测试“变绿”。
- 已记录历史结构债单独列出；本次新增不合格代码不能以历史债为理由放行。

### 11.3 三类故障验收

- 断外网、本地 LAN/API 可用：知识/向量/助手、Web 与手机在线业务仍正常。
- 手机与 API 断开：阶段 9 离线任务/草稿工作，不能假装在线提交；联网补传无重复。
- API 退出或 Docker 重启：Web 明确失败，恢复后数据/媒体/会话/回执仍在。
- 磁盘不足、缺模型、坏索引、缺媒体等关键故障给出可定位提示，不宣称已完成。
- 端口占用和重复启动有明确行为，筑瞳与查寝同时运行，代理不能请求到错误项目。
- 核验角色/范围、跨数据集 ID、过期 rev/epoch、重复键与恶意文件等既定错误路径。

### 11.4 完整备份与恢复

- 扩展阶段 2 备份，覆盖数据库、原媒体、模型清单/必要模型文件、知识源、索引和配置说明。
- 模型/索引可由独立交付目录备份，但清单必须准确引用版本和哈希，不只备份 SQLite。
- 恢复到新目录/新环境，按清单验证字节、表数量、外键、索引版本和受保护媒体读取。
- 演示运行备份保管内部会话密钥；面向外部分发的交付包不包含有效令牌、私有密钥或不必要个人数据。
- 对外安装包可初始化新的演示身份会话；恢复备份与发布包是两种用途，分别说明。
- 不覆盖正在运行数据库，不执行 Docker 卷清空作为常规恢复方式。

### 11.5 离线交付包

- Web/API Docker 镜像及镜像归档、Compose 与必要环境示例，数据库初始化/迁移工具。
- Flutter Android APK、版本与 SHA-256、真机连接及必要权限说明。
- 本地模型全部文件与许可、知识源和版本、SQLite 向量或可离线重建所需依赖与脚本。
- 测试数据、完整媒体、场景清单、备份、文件哈希清单、启动/停止/更新/恢复说明。
- 若声称可离线源码安装/重建，必须另含相应依赖缓存并实测；只有镜像/APK 时只承诺离线部署运行。
- 第二台机器提前安装 Docker 等基础运行环境；若要从全新系统完全断网安装，基础安装包也需列入并实际验证。
- 避免只在原机器构建缓存、宿主机目录或浏览器 IndexedDB 存在时才可运行。

### 11.6 换环境与比赛排练

- 在第二台机器或独立干净环境依据文档导入镜像、配置持久化目录、初始化并启动。
- 第二台真机/同台重新配置连接，对五条路径分别记录结果、耗时、对象和实际限制。
- 固定验收问集全量运行，保持阶段 6/7 指标；关键业务、引用和对象绑定必须全部正确。
- 外网关闭后冷启动，不依赖预先在线加载的模型或浏览器资源，再完成一次全流程。
- 以阶段 6 目标机测得的冷启动/预热性能作对比，记录硬件与数据量差异，不只报告最佳一次。
- 准备比赛步骤卡、固定提问、失败时恢复步骤、演示备份及可回放录屏；录屏只作备用展示，不代替验收。

## 最终交付报告

提交版本总表、所有阶段审核结论、自动测试摘要、第二环境部署记录、五条路径实录、
知识问集全量结果、性能记录、备份恢复核验、交付包清单/哈希、已知限制和比赛操作卡。
最终通过的判据是另一环境可重复运行且事实一致，不是单台机器上截到成功页面。
