# 阶段 9：Android 离线办理与可靠同步

目标：已下载任务在手机业务网络断开时可查看、填写、拍照并保留，重启后继续；联网后不重复、不串身份、不覆盖新状态。
前置：阶段 8 真机在线流程通过；阶段 4—5 的幂等、rev、epoch、回执已验证。
采用有限的现场任务离线能力，不做任意管理功能离线编辑或通用多主数据库同步。

## 实施步骤

### 9.1 离线边界与本地模型

- 可离线：已下载任务及必要档案、清单作答、到点尝试、现场照片草稿、问题草稿、工单办理草稿。
- 不可离线权威生效：派工、审核、验收、关闭预警/问题、规则/计划/身份权限变更及场景复位。
- 定义哪些现场动作可先记录后提交，哪些工单动作必须等前一步在线确认；任务快照不足时禁止编造。
- 本地使用持久化数据库与应用文件目录，保存远程快照、草稿、附件和操作队列；包依赖与 schema 版本固定。
- 快照记录身份、服务器地址、datasetId、epoch、实体 ID/rev 和下载时间；未下载的任务明确不可离线办理。
- 照片复制到应用管理目录后再登记草稿，不能依赖相册临时 URI 或缓存目录。

### 9.2 固定操作与持久队列

- 操作包含 operationId、固定幂等键、身份、数据集/epoch、目标 ID、expectedRev、请求摘要、依赖与重试信息。
- 草稿可编辑，已入队的请求快照不可悄悄改内容；修改内容形成新的逻辑提交键并保留前后关系。
- 队列至少区分待同步、上传中、提交中、等待重试、冲突、永久失败、已确认完成。
- 队列状态与本地草稿更新同事务；应用在每个状态被强制结束后都能恢复可解释状态。
- UI 区分本地已保存、等待服务器确认和服务器已完成，不能全部显示“提交成功”。

### 9.3 文件与命令依赖

- 先上传原件/缩略图并保存返回 mediaId，再提交上报/检查/完工命令；依赖未完成不得抢先提交。
- 附件 upload key、draftId、业务 operationId 固定，重试复用，避免同一照片重复占用配额。
- 已上传但未关联的文件在重启后继续关联；禁止无限重复上传或自动删除仍被草稿引用的字节。
- 超时意味着结果未知：先查同键回执或重发同一请求，由服务端回执消除重复副作用。
- 业务动作成功但本地确认前崩溃，再次同步得到同一结果，不追加第二条审计/状态节点。
- 同目标有多个动作时串行提交；后续动作基于已确认结果重建合法请求，不能伪造本地服务端版本。

### 9.4 重试、冲突与身份隔离

- 对连接失败、超时和可重试服务错误做有上限退避；验证错误、越权和状态冲突不无限重试。
- 版本冲突展示服务器当前状态与本地草稿，允许刷新后重新提交或放弃；禁止静默最后写入覆盖。
- epoch 冲突隔离整组旧操作，提示演示数据已复位；不得把旧队列自动绑定新数据集版本。
- 切身份/服务器/数据集后暂停原队列，不用当前身份替另一身份提交；返回原身份后再确认恢复。
- 内部会话失效时重新核验同一身份；后端已禁用或收窄范围则保留草稿并停止相关提交。
- 同步触发来自启动、联网、回前台或手动重试，但只有一个执行器可处理同一操作。

### 9.5 真机故障注入

- 区分外网断开（本地 API 仍通）、手机与 API 断开、API 服务停止；分别记录实际操作。
- 在拍照后、入队后、上传后、业务提交后响应前、本地落完成状态前强制结束应用。
- 恢复网络并重复点同步，核对服务端对象、附件、状态节点、审计和回执数量。
- 并发由 Web 修改同一工单/任务，验证手机旧版本不覆盖；权限变化与身份切换不泄漏草稿。
- 用隔离测试数据集模拟 epoch 变更，验证旧队列被隔离；阶段 10 再用真实复位操作联合复验。
- 不同操作的独立上报仍要形成独立记录，不能为了“防重”误合并真实新上报。

## 交付物

离线范围表、本地 schema/升级、队列状态转移与错误处理契约、持久文件策略、同步执行器、
服务器回执查询/复用能力、冲突 UI、真机故障注入日志和前后数据对账。
如需追加后端接口，只扩展现有业务命令，不另造绕过授权的批量任意写表接口。

## 必验清单

| 编号 | 验收条件 |
| --- | --- |
| S9-01 | 断网能查已下载任务和必要资料，未下载内容明确不可用 |
| S9-02 | 断网填写/拍照/入队后杀应用重开，草稿、字节、提交标识和状态不丢 |
| S9-03 | 联网先上传后关联/提交；上传后中断可续办，无重复媒体和错误配额占用 |
| S9-04 | 提交已成功但响应丢失后重试，同一操作副作用一次，返回原回执 |
| S9-05 | 连续触发同步/重试至少 10 次，同一逻辑提交仍只有一个对象及一次状态动作 |
| S9-06 | 旧 rev 与服务端新状态冲突可见，保留草稿、不覆盖；非法状态不无限重试 |
| S9-07 | 旧 epoch 操作隔离且不能写入新版本；不能静默重绑 epoch |
| S9-08 | 切身份/服务器/数据集不串队列；会话失效和权限变化不导致代提交或数据泄漏 |
| S9-09 | 各关键中断点可恢复，无永久卡在“上传中”的无处置队列，失败原因和重试入口明确 |
| S9-10 | 本地/待同步/服务端成功清晰区分，在线阶段 8 回归通过，真机数据库和媒体对账一致 |

交付证据须有真机杀进程和断网录屏、固定 operationId、服务端回执与对象数量核对。
不承诺传输只发生一次；要求重复传输的业务副作用只执行一次且结果可查询。
