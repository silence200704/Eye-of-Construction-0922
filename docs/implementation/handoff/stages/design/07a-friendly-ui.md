## 7A.1 品牌与素材

- Web保持现有校园青主题，改为丰富卡片、背景图案、校园插画与按压/滑移/展开等反馈。
- 通过MCP读取Bencho、Uiverse、Aceternity、Kinetics的适用组件，记录参考到实现的映射；
  Vue端不因参考React示例迁移框架，触屏/减少动效模式保留等价操作。

- 盘点现有Web、小瞳形象、截图、图标和素材来源；保留业务对象与来源语义。
- 制作校园守护主题板：校园青/暖白/晴空蓝、圆润小瞳、校园建筑与路径图案。
- 交付小瞳6状态、校园插画4幅、空态6幅、图案4套、首批业务图标16个、流程图形3套。
- token包含正常/告警/失败/历史/本地/待同步等语义；不以颜色单独表达状态。
- 形成可编辑源文件、导出资源和许可/版本/AI辅助清单；首屏素材离线可读。
- 一次集中确认视觉方向、关键页和小瞳后再扩展；不要求每个小图标单独审批。

## 7A.2 双端关键页原型

- Web：总览、地图/趋势、预警详情、巡检、问题/工单、小瞳引用、报表/设置。
- App：工作台、三类监测/设备、预警处置/台账、统计、任务与到点、上报、工单、同步中心、我的。
- 关键页同时给正常/加载/空态/失败/无权/提交/冲突状态，不能只画漂亮首页。
- App使用原生导航、控件、系统返回和窗口规则；Web保留键盘、表格效率和宽屏分析。
- 明确假数据标注位置、现场照片与装饰插画的区别、同步状态的真实触发条件。

## 7A.3 Web分批落地与App交接

1. 先建Web语义token、共用图标/小瞳/空态/状态/表单反馈组件，避免逐页散落颜色和文案。
2. 总览与导航作为首批，再覆盖预警/任务/问题工单/小瞳/报表；每批验证业务和来源不变。
3. 地图/3D/趋势保留可读图面；高信息密度区减少装饰，不把图案叠在真实证据和图例上。
4. App本阶段交原生可实现的原型/状态/资源，实际ArkUI页面在阶段8/9落地，不交H5壳。
5. Web若有必须拆分的旧大组件，只做当前接入所需小范围调整，不能趁换肤重写业务状态机。

## 7A.4 传播模板与匿名版

- 交主海报、3张场景海报、协同图、16:9答辩/录屏封面和可选9:16模板。
- 评审版与公开传播版分开；正式DOCX/PPT/视频内不出现学校/队伍/指导教师等身份信息。
- 阶段10再用已验收功能的真实截图/录屏替换模板，不在原型阶段伪造实际界面。
- 宣传讲清OpenHarmony原生软件、模拟监测和业务闭环；不声称GPIO/I2C或实体声光已接通。
