# 阶段 5：点检巡检、问题、工单、保养与报表

目标：把现有现场业务闭环迁移到后端，并由Web完成真实办理，为OpenHarmony原生App复用同一接口。
前置：阶段 4 的身份/范围、命令上下文、版本、幂等与审计通过；阶段 2 媒体接口可复用。
保留当前六种问题审核出口、工单和复查语义，不自行简化为一个“完成”按钮。

## 实施步骤

### 5.1 权限与状态转移表

- 阅读 core/inspection、stores/inspection、core/maintenance、相关仓储和测试，逐动作记录前置条件。
- 分别定义任务、点位检查、问题、工单、复查、保养状态；不能共用一个 done 状态。
- 计划/审核/派工/验收由原业务允许身份执行，safety 负责工单验收；历史 reviewer 不新增为身份。
- 维修人员接单必须匹配被派工人；物业值班代接保留原允许规则并要求原因。
- 服务端按身份 ID 授权；原人员姓名和角色文本只作历史，不因同名自动授予权限。

### 5.2 计划、任务与到点

- 实现点检/巡检计划，保留按设备/按路线、周期、范围、清单、执行角色和启停。
- 按计划与执行时刻生成任务，事务和唯一约束防重复；手动生成无需引入复杂调度平台。
- 任务冻结生成时的范围/清单/角色快照；修改计划不回写已生成任务。
- 虚拟 NFC 校验测点标签及版本；人工兜底必须写原因；成功失败尝试均留痕。
- 到点与完成分开：必答项未完成、未检查点、异常无后续动作都不能假装检查完成。
- 保存逐点作答、异常说明、创建问题或无需建单依据；部分完成与逾期分别计算。

### 5.3 上报与问题审核

- 统一传感器、巡检、人工、保养四种来源；保存原始描述、位置、照片和来源链。
- 使用一次上报固定 submissionId 和幂等键，重试复用；不按同人同日或时间桶合并独立上报。
- 落实转维修、转专业排查、安排复查、退回补充、关联既有对象、无需处理并关闭六种出口。
- 保留二级分类、审核说明、无照片原因和原始报告，审核不得覆盖原描述。
- 关联已有问题/事件检查真实存在、范围、不能自关联；双向关系同事务更新。
- 已关闭目标的例外关联保留原说明要求；疑似重复由人审核，不自动合并或删除。

### 5.4 工单、验收与复查

- 实现 created→assigned→repairing→submitted→verified 或 returned 的合法转移及退回再办理。
- 派工需指定维修人；完工需措施和原要求的照片/材料；验收退回需理由。
- 工单验收通过与关联问题进入 pending_recheck 同事务；不能直接关闭问题或预警。
- 登记复查事项、责任人和日期；保留每轮结论、证据和历史。
- recovered 关闭问题；observing 登记下一轮；recurred 回到待审核继续处置，不另造无关问题。
- 事件关闭只允许使用当前事件关联的已验收工单或合法无需维修依据，不能借同测点旧工单。
- 检查任务完成、工单验收、问题关闭、预警关闭是四个独立结果。

### 5.5 附件与保养

- 复用媒体上传和内容读取；完成所有权、归属、类型、配额与授权关联的业务接入。
- 按现有规则执行每归属最多三张、总计 600 KB 的照片限制；前端压缩不能代替服务端检查。
- draftId/mediaId 关联补传；上传成功但业务未提交可以重试关联，不重复建照片或错误占用配额。
- 照片仅有一个问题/工单/保养归属，缩略图与原件可核对，未上传成功不得标为证据已提交。
- 保养计划、周期任务、执行清单、结果、下次日期和历史持久化。
- 保养发现异常转出问题，任务执行记录与问题双向关联同事务；重试不能多建问题。

### 5.6 报表与 Web 收口

- 接入任务、问题池、工单、复查、保养、报表和单事件打印/CSV 的服务端读取。
- 明确统计粒度、时间范围、归档口径；观察中不算最终闭环，不能把验收率当问题关闭率。
- 列出仍使用 IndexedDB 的入口，逐一关闭日常业务写入或标明仅旧快照导出用途。
- 场景自动执行器和助手补齐入口的写适配在阶段 7/10 迁移，本阶段禁止它们绕过后端制造混合数据。
- 共享命令结果、错误提示和冲突刷新机制，不让各页面重复实现权限与状态机。

## 建议交付物

巡检/保养计划任务接口、到点/作答/上报命令、问题审核/关联、工单派工/接单/完工/验收、
复查轮次、附件关联与报表查询契约；对应 Web 接入和完整角色/状态转移矩阵。
所有新写入使用阶段 4 的事务、审计、回执、rev 与 epoch 机制。

## 必验清单

| 编号 | 验收条件 |
| --- | --- |
| S5-01 | 重复生成不重复任务，改计划不改变既有任务快照 |
| S5-02 | 错误标签不能到点，人工签到需原因；到点不等于完成，未答必答项不能完成 |
| S5-03 | 四种来源可追溯；同次上报重试只建一次，独立上报不被同日规则误合并 |
| S5-04 | 六种审核出口及二级分类/依据有效，原报告保留，错误动作返回明确错误 |
| S5-05 | 关联问题/事件及保养转问题双向一致；自关联、跨范围和不存在目标被拒绝 |
| S5-06 | 派工/接单/完工/退回/验收权限与字段校验有效；维修人员不能自行验收 |
| S5-07 | 验收只推进待复查；恢复/观察/复发三种复查分支与轮次历史正确 |
| S5-08 | 当前事件关闭不借用旧事件工单；不满足恢复或处置依据时拒绝关闭 |
| S5-09 | 照片真实可读，数量/体积/归属校验和补关联有效，重试不重复占配额 |
| S5-10 | 事务中途失败后问题/工单/任务/附件关联/审计/回执无部分提交 |
| S5-11 | 报表、导出和打印可从数据库明细重算，观察中、部分完成等不混算 |
| S5-12 | Web 关键链路全部读写后端，刷新/重启/另一浏览器一致；角色/rev/epoch/幂等回归通过 |

至少演示两条闭环：设备问题→维修→验收→复查恢复；结构问题→专业排查/观察→复发。
另演示一次保养异常转问题、一次退回补充、一次验收退回。
报告需附每种状态变化与对应数据库对象、附件、审计及回执证据。
