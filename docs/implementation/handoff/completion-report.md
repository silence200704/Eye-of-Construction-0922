# 阶段完成度报告模板

每阶段复制此模板填写。未知、未跑或没有环境的项目请如实标记，不填预计结果。
报告与代码应对应同一提交，避免用旧截图证明新代码。

## 基本信息

- 阶段编号/名称：
- 对照计划版本或提交：
- 本阶段代码分支、起止提交 SHA：
- 报告日期、测试系统、设备：
- 启动方式、页面/API 地址：
- 数据集 ID、datasetEpoch、Alembic head：
- OpenHarmony SDK/API（≥12）、DevEco/Hvigor/OHPM、HAP签名/设备或模拟器版本（涉及App时）：
- 赛题3对应项、模拟输入/声光边界、视觉与资源版本、正式材料匿名检查（涉及时）：
- 本轮变更摘要：
- 自评完成度：已验证通过 __ / 必验 __；已实现未验证 __；失败 __；未实现 __。

## 逐项完成情况

| 验收编号 | 四态结果 | 实现文件/提交 | 测试或复现步骤 | 证据路径 | 差距 |
| --- | --- | --- | --- | --- | --- |
| 例如 S4-01 | 未实现/已实现未验证/验证通过/验证失败 | | | | |

填写该阶段全部验收编号。不能只挑完成项；计划调整单独说明，不直接删除未完成项。
若一个编号含多条断言，列出各断言结果，全部通过才能把整项标为验证通过。

## 接口与数据库

- 新增/变更 API、请求 DTO、响应示例、错误码与契约文件：
- 身份/范围校验、expectedRev、Idempotency-Key、datasetEpoch 的实测结果：
- 一次成功写入前后的对象 ID、业务状态、行版本、审计与回执数量：
- 同一请求重试、同键不同内容、并发冲突和失败回滚的证据：
- 迁移版本、空库升级、旧库升级、升级前备份及恢复核验：
- 媒体文件、元数据及 SHA-256 核对结果：

不要贴令牌、密钥或含凭据的配置；示例脱敏，但保留对象关系与错误结构。
没有数据库或接口变更时填“不涉及”并说明依据。

## 真实操作证据

每条关键路径给出：前置数据→操作身份→动作→预期→实际→对象 ID→截图/录屏/日志。
至少说明页面刷新、API/应用重启、另一个浏览器/设备读取后的结果。
涉及断网时说明关闭的是外网、手机业务网络还是后端服务，三种不能混写。
涉及耗时要提供硬件、数据量、冷启动/预热、样本数与统计口径。

## 回归与限制

- 已回归的前序阶段和固定演示路径：
- 筑瞳与查寝同时运行结果：
- 仍读取/写入旧 IndexedDB 或本地假数据的功能及原因：
- 新发现结构债、风险、最小修复建议；是否涉及需确认的大范围重构：
- 已知问题：严重度、复现步骤、影响、计划去向：
- 未完成项、阻塞、下一阶段前置条件：

## 提交审核的材料

- 代码位置/提交或可审查补丁：
- 验收清单、测试日志、截图/录屏、数据库脱敏核验结果：
- HAP/镜像/模型/视觉资源/交付包路径及SHA-256（涉及时）：
- DOCX字体行距、MP4时长/大小、PPT讲解时长、三类材料匿名与RAR检查（阶段10/11）：
- 需要重点审核的疑问：

审核后填写：结论、问题编号、需补证据、必须修复项、复验结果。
阶段标签及实施台账的“通过”状态在审核通过后更新，不能仅根据自评先标通过。
