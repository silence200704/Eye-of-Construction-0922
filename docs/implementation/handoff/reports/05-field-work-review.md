## 必须返修的代码问题

### R5-01 · P1：多个写入口缺少目标楼栋范围校验

位置：`operations/field/reviews.py:199`、`orders.py:185`、`maintenance.py:334`、`inspection.py:157`。
get_issue/get_order/get_plan 等仅按数据集取对象，不校验楼栋；部分写入口只做角色和 rev 校验。
有照片时 link_photos 才附带校验，导致权限取决于请求是否带照片。

临时库将 safety 的合法服务端范围设为 `buildingIds=[]` 后，范围外问题审核、巡检计划停用、
工单派工、无照片保养执行均返回 **200**，预期应为 403 且不产生业务修改或成功回执。
批量生成也只遍历全数据集启用计划，没有根据操作者范围筛选。

最小方案：增加共用目标上下文/授权函数，所有修改先对原对象校验范围；迁移归属还需校验新归属。
工单位置同时考虑测点及关联问题，不能让没有 pointId 的工单绕过楼栋范围。
生成任务按明确范围规则执行。权限不能依赖照片等可选字段。
补 `None/[]/[允许楼栋]`、同数据集越权、带照片/不带照片、生成与修改的回归。

### R5-02 · P1：接单可以自改维修人，且按姓名/角色标签授权

位置：`operations/field/orders.py:100`、`domain/inspection/orders.py:21`。
候选工单在鉴权前无条件合并 payload.assignee；repairing 的身份校验随后读取被请求改写的维修人。
实际将工单派给“其他维修人员”，demo-repair 接单时附 `assignee=演示维修人员`，返回 **200**，
维修人变成自己，状态 repairing。submitted 也没有要求当前办理人匹配工单责任人。

此外 is_assigned_to 比较姓名/角色标签，违反阶段计划“按身份 ID 授权，历史姓名不授予权限”。
契约开头说按 ID，工单节却改成按姓名/标签，不能用改契约绕过原计划。

最小方案：以服务端持久化 assigneeId 校验原工单；assignee 只在允许派工动作修改。
接单、完工限制字段，物业代接保留原派工人与代接原因；历史姓名保留展示，需要重新派工才能授权。
如需新列，追加迁移，不能改旧迁移。验证篡改 assignee、同名不同 ID、角色标签、错人完工均拒绝。

### R5-03 · P1：人工上报可伪造事件归属，并用于关闭另一测点预警

位置：`operations/field/issues.py:131`、`reviews.py:75`，影响 `datasets/alarms/commands.py:132`。
只有 sensor 入口校验事件与测点；非 sensor 的 _build_issue 仍直接保存 payload.eventId。
审核生成工单继承该 ID，关闭事件仅按 event_id + verified 查询工单，因此错误关联成为有效关闭依据。

实际链路：人工测点 B 的 report 问题私填裂缝测点 A 的事件 ID → 转维修 → 验收 →
A 满足恢复条件 → 空 noRepairNote 关闭 A，最终返回 **200**。
两测点 ID 不同，不能视为已验证“仅当前事件工单可关闭”的充分实现。

最小方案：拒绝非对应来源携带未经校验的来源字段；需要关联事件时走明确的服务端校验入口，
校验存在性、数据集、楼栋范围、测点一致性及授权，工单关系从已验证来源派生。
关闭时校验工单确属合法当前事件处置链，不只相信客户端间接写入的 event_id。
补跨测点、跨楼栋、不存在事件、普通上报伪填事件及合法传感器链路对照测试。

### R5-04 · P1：问题审核缺少周期约束，可跳过新工单验收直接闭环

位置：`operations/field/reviews.py:199`、`domain/inspection/issues.py:75/107`。
审核只拒绝 closed，其他状态可任意重选出口，to_repair 每次都新建工单。
实际同问题两次转维修，换键并带当前 rev，均 **200**，形成两张未完成工单。

另一路全通过公开接口复现：安排复查并登记一轮 → 转维修生成新工单 → 再安排复查 →
直接给旧轮次 recovered，问题 **closed**，关联新工单仍 **created**。
本轮登记、处置、验收与结论没有绑定，旧轮次绕过新处置要求。

最小方案：冻结允许的审核转移和重复转维修规则；已有待办工单时拒绝重复或显式复用。
新处置周期开始时保留但终止/标记失效旧待结论轮次，或绑定处置轮次/工单并校验有效性；
不能静默删除历史。对新维修分支，未验收不得沿用旧轮次关闭问题。
覆盖重复点击、观察转处置、复发再维修、退回再办理和多轮复查，保留六种合法出口。
