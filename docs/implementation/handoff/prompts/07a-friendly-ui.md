# 阶段7A执行提示词

请在现有筑瞳项目实施阶段7A。先读AGENTS.md、实施台账、阶段7当前审核状态，以及：

- stages/design/07a-friendly-ui.md；
- design/competition-visual-system.md、design/harmonyos-native-app.md、design/competition-scope.md。

以上路径以docs/implementation为范围，stages位于其handoff目录。不要使用旧Flutter/Android方案。

## 工作顺序

1. 盘点当前界面、素材许可、小瞳与可复用组件，形成“校园守护”主题板与关键页原型。
2. 采用校园青/暖白/晴空蓝、圆润小瞳、建筑/窗格/树叶/路径图案；允许丰富美术，关键数据区留清楚的底。
3. 一次集中确认品牌、小瞳、图案密度和Web/App首页原型，再扩展素材与页面；不逐小图标索取确认。
4. 完成规定素材组、可编辑源文件、导出和版本/许可/AI辅助清单；离线可用，不依赖CDN或在线字体。
5. Web先token/共用状态组件，再总览、预警、巡检、问题工单、小瞳引用、报表与设置；每批验证原业务。
6. App交OpenHarmony ArkUI可实现的监测/预警/统计和现场业务原型，阶段8落地；不交WebView页面代替原生。
7. 覆盖加载/空态/失败/无权/历史/待同步/冲突，不让装饰或成功动效掩盖真实状态。
8. 评审模板匿名，主海报/场景海报/协同图与正式视频/PPT规格对齐；未完成页面只标原型。

阶段7返修优先，7A设计可并行；不重写AI、后端状态机，不碰查寝，不清库，不采购南向硬件。
模拟输入/声光与真实现场照片严格区分。按S7A-01—08提交报告，视觉设计、Web实现与App原型分别记完成度。
宽窄屏、可达性、资源性能、Web回归/类型/构建必须有真实结果；App实际页面仍待S8/S9验收。
