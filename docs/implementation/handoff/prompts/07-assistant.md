# 阶段 7 开发提示词

请在现有筑瞳项目上实施阶段 7“小瞳业务问答、知识解释、证据与会话”。
先读 AGENTS.md、实施台账、阶段5最终复核、阶段6报告及 knowledge-v1 契约，
再按 `docs/implementation/handoff/stages/07-assistant.md` 的 S7-01—S7-10 逐项执行。
阶段6已交付管理/检索，但小瞳尚未接入；不能把既有演示回答当成新服务已接通。

## 实施顺序

1. 盘点并冻结小瞳现有预设题、自由输入、视觉/视频/比较/趋势/试算/回放及深链回归清单。
2. 定义意图、对象ID、知识引用、实时事实版本、身份/数据集/epoch和会话DTO；先写关键失败测试。
3. 接服务端动态业务查询：当前事实由阶段4—5接口读取，不能用IndexedDB或旧内存默认值回答。
4. 接阶段6混合检索和澄清/缺依据分支；结论、知识来源和业务事实分别显示，支持引用查看。
5. 对象优先级：本轮显式对象覆盖旧上下文；同名/缺对象先澄清；换身份/数据集使不适用上下文失效。
6. 补正式会话和媒体会话持久化，必要时追加迁移；保存结构化答案、对象、引用、回执和页面定位。
7. 刷新恢复必须暂停只读，不重放写命令、自动导览或媒体处理；迟到响应不能覆盖新轮次。
8. 复用现有视觉算法与来源标记，接正式媒体内容接口；趋势/试算使用权威数据，试算不建事件。
9. 导航到正确地图/3D/影像/事件/工单对象，关闭遮挡层，回退不被迟到响应重新打开。
10. 冻结至少20道有明确数据库前置状态的业务/多轮题；结合原60题逐题验证、备份恢复、部署和报告。

## 不可变约束

- 不接外部生成或embedding API；仅本地数据、BGE检索和本地解释模板。
- 不新增登录、账号密码；五类预置身份由服务端授权，不能靠前端隐藏代替权限。
- 知识和用户文本是数据，不能变成越权查询或办理指令；建议不等于已执行。
- 准备/办理必须调用既有真实业务命令，失败可见；结果、审计、幂等回执同事务。
- 不改动查寝工程或8000/5173；筑瞳继续18000/8080/5180，不清空演示数据或Docker卷。
- 文件≤450、函数≤80、参数≤5、目录文件尽量≤8；只拆本次接入所需职责，不大范围重构。
- 原冻结60题不改答案不逐题硬编码；阶段6已有3题非正确直答，保留记录，不能宣称60/60。
- 阶段8 Flutter和阶段10统一演示控制仍不提前实施。

## 提交与审核

按小步 RED→GREEN 提交，每个S7编号登记实现/核验/证据。至少20道业务/多轮题关键事实、
对象ID绑定和引用须100%正确；知识题保持阶段6门槛，引用有效率100%。
补身份/范围/数据集隔离、迟到响应、业务变更后重问、无数据、API断开及外网阻断测试。
保留真实页面/HTTP/数据库/文件证据，全量后端和前端检查、类型检查、构建、结构门禁通过。
最终提交 `07-assistant.md` 完成报告、契约、逐题结果及回归记录，完成后核验本阶段，
未通过项如实保留，不直接进入阶段8。
