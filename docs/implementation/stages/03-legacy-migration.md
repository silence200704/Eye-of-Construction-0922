# 阶段 3：旧数据迁移

核验日期：2026-10-18。结论：本阶段交付与验收门槛通过，可进入阶段 4。
代码开发的 RED/GREEN 检查点已保留；端口隔离及重复启动修复也在本阶段收尾前完成。

## 已交付

- Web 设置页导出当前浏览器旧主库、完整演示库、可获取内存状态及随包素材。
- 旧库只读打开，不升级或修改原库；不存在的库明确列出，不新建空库。
- 支持旧 v1—v7 JSON 备份及迁移集合；17 张旧表保留原编号、时间、来源和历史人员。
- 服务端先预检再提交：字段、唯一性、跨数据集外键、嵌套引用、文件字节和哈希校验。
- 同一快照重复导入复用；冲突整包回滚，预检不提交，文件失败补偿清理。
- 照片、缩略图、视频、关键帧独立存储；偏好、会话、场景与分析比较结果持久化。
- 提供逐表数量、字段/文件校验、缺失/错误报告、报告导出、历史记录及核对快照接口。
- Alembic 0008 区分旧监测修订次数与服务端行版本，保留旧 revision=0。

## 本阶段边界与下一阶段

当前完成的是旧快照导入与核对；业务页面仍明确展示浏览器数据来源，日常新增与修订尚未全部走后端。
会话、场景按暂停只读快照保存，UI 恢复分别在阶段 7、10 接入；既有 AI 逻辑没有改动。
其他浏览器/端口需自行导出相应来源快照，再通过迁移入口导入；刷新前已丢失内存数据不能恢复。
历史结构债继续按基线台账管理，不借此进行大范围重构。

阶段 4 将迁移楼栋/楼层/测点/设备、基准与规则版本、监测录入/修订/CSV、预警及通知，
并核验旧样例判定一致性、状态流转和跨浏览器读取。阶段 3 不宣称这些新业务接口已经完成。
