# 离线独立上报、持久照片与固定提交队列 v2

日期：2026-10-31。代码`47e5f17`。本批扩展[首批随身包](local-pack-v1.md)，仅覆盖下载过的活跃测点上的**独立问题上报**。
不是完整离线巡检/工单，也不允许离线派工、审核、验收、关闭问题或预警。

## 本地库与文件

原生`zhutong_offline.db`升级schema2；新增offline_reports、offline_operations，两表完整内容按scope分区保存JSON。
升级在事务中建表并更新版本，保留schema1快照与笔记；未知未来版本不清库、不降级覆盖。立即离开页面会等待初始化/已排队事务结束后关闭。
本地草稿ID独立生成，首次创建即固定测点/楼栋/楼层；编辑不能换成另一个目标。

照片通过既有PhotoSelector压缩为上传用JPEG后，写入filesDir/offline-media持久目录，单张≤200KB，合计≤3张/600KB。
持久文件保存size/SHA-256及draftId，上传前重新读取并校验路径/大小/SHA；不使用相册临时URI或cacheDir作为上传来源。
同一draftId不同字节报冲突，不覆盖原件；写入先临时文件后改名，短写入拒绝。字节不进入ArkUI状态，状态只保存路径等元数据。
草稿引用只在文件保存成功后落库；崩溃于文件保存和引用落库之间可能留下未引用文件，本批保留而不自动回收。不能声称覆盖所有拍照中断点。
解除草稿照片引用不自动删文件，避免误删别的固定操作仍引用的字节；配额外的持久目录全局回收留待后续。

## 草稿与入队

入口：我的→离线随身包→离线上报。文字变化异步自动写入本机，界面区分“正在保存”与“本地已保存”；写入未完成前强杀不保证最后一次输入。
相册/拍照选择仍取决于设备能力。外部选择器期间保持页面上下文，回来后保存持久字节和引用，再释放临时缓存。
“保存并加入待同步队列”校验必填，事务内冻结草稿并创建唯一operation；失败整体回滚。同一草稿重复入队返回同一操作，不创建第二份。
入队后原始目标、文字、照片元数据不可编辑；不同真实上报使用不同草稿/operation，不以“防重”合并真实新问题。

## 固定请求与执行

媒体key固定为operationId-photo-draftId；业务key固定为operationId-commit，submissionId为operationId。
先逐张读取校验并上传，持久记录返回的mediaId/SHA；齐备后生成并持久化commitBody，之后重试字节、key、目标均不改变。
本批存原始冻结body作为请求快照；没有另存客户端正文摘要，服务端仍使用既有幂等摘要校验。
每个scope只有一个本机执行器；同步前、每次上传前后及提交前后复核当前会话身份/范围、epoch与目标活跃状态，不存token或替其他身份提交。
执行只在用户点同步时触发，不依赖永久后台服务。网络重试指数退避，最多5次；早于等待时间点击不发送，不消耗新尝试。
uncertain在可能发送POST前落库，收到完整回执后清除；因此能区别“尚未发出”和“结果待核验”。
上传或提交成功但响应丢失/本地完成落库前中断，重开后可使用原媒体/原业务key和已冻结body核验；不重新生成标识。
完成回执与草稿done同一事务落库，之后才向在线工作区发布结果；页面回填失败不能撤销已确认的本地完成记录。

## 状态和边界

| 状态 | 含义与操作 |
| --- | --- |
| editing / queued | 仅本地草稿 / 内容已固定待同步，不能说已上报 |
| uploading / sending / waiting | 照片或业务结果待核验；重启后保留标识，手动原请求重试；尚未发出时明确等待连接 |
| blocked | 身份/权限/目标不可用，停止写入；用户明确重新核对后可再做授权检查 |
| conflict | 409冲突，原稿保留，不改body自动覆盖；当前没有变基解决界面 |
| isolated | epoch变化，旧操作隔离，不重绑新epoch |
| failed | 验证或照片完整性等永久错误，停止上传，保留原始内容 |
| done | 服务端有完整问题回执；只代表问题创建成功，不代表已关闭 |

当前没有完整检查清单和工单离线命令、任务关联问题队列、多命令依赖图、自动联网同步或冲突重建UI。
重试上限与冲突态不删除原稿，也不提供“换key重发”规避未知结果。文件/SQLite测试及本机API替身不等同设备杀进程、断网或正式后台行为实测。
