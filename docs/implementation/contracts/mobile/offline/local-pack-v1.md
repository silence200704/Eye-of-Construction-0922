# 原生离线随身包与现场笔记 v1

日期：2026-10-30。阶段9首批范围：显式下载的任务/档案/监测快照，以及手动保存的任务现场笔记。
不是离线业务提交或同步队列，不将本地保存解释为检查完成、上报成功或工单完工。
后续2026-10-31的schema2/独立上报队列见[outbox-v2](outbox-v2.md)，以下schema1与“不含照片/队列”描述首批历史边界，不是最新完整状态。

## 存储与隔离

使用OpenHarmony `relationalStore`，私有数据库`zhutong_offline.db`、SecurityLevel.S1；不以preferences保存业务记录。
`offline_schema`保存schema版本1；`offline_packs`保存快照JSON；`offline_notes`保存任务笔记JSON。
SQLite单条upsert原子写入完整JSON，调用在同一Vault内串行；未知schema拒绝打开，不清库或降级覆盖。

快照owner是规范化服务地址、`demo-main`、最后核验身份ID的组合。不同服务/身份不共享快照。
笔记scope再包含数据集epoch、身份角色和排序后的楼栋范围指纹；不同epoch/范围互相隔离，旧记录保留。
快照只序列化明确的身份、业务workspace、scope及下载时间，不序列化ApiClient、token或会话。

快照来自App已完整读取的当前授权数据。离线无法获知服务端最新权限，界面明确“最后下载快照，当前权限待联网核验”；不宣称为实时监测。
冷启动网络不可用时，可从“我的→离线随身包”读取连接设置中最后核验身份的包；没有下载过则明确不可用，不构造空正常数据。
在线已发现身份范围/epoch变化时，不展示旧scope包，提示重新下载；旧笔记不自动绑定到新版本。

## 笔记

仅允许包内任务，记录taskId、expectedRev、text、updatedAt，最多4000字。保存笔记不发任何业务HTTP请求。
首次保存采用当时下载的任务rev；以后刷新同一任务或继续编辑，不悄悄将原笔记依据改为新rev。
页面显示笔记依据版本；与当前下载任务版本不同时提示冲突依据待核对，为下一批同步处理保留信息。
写入失败保留旧值并显示本地失败；下次保存可以重试，不将失败显示为本地成功。
只有点“保存到本机”后的文字保证落库，未保存的输入仍是页面内存；切换任务时会先保存当前任务文字，保存失败不切走。

## 当前边界

本批不保存照片原件、不持久化完整巡检答案、不冻结HTTP命令、不上传或自动同步。
本批没有预警确认/关闭、派工、审核、验收等离线权威写入口。
下一批接原生持久媒体、冻结operationId/幂等键与请求摘要、事务队列、同目标依赖和错误/冲突恢复。
