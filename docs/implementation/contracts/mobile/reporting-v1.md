# OpenHarmony问题与照片在线上报 v1

2026-10-28实施，2026-10-29收口。复用[现场业务契约](../field-work-v1.md)，无新增迁移，head仍为0013。

## 来源与写入

- 独立发现：从工作台问题池或测点详情进入，可绑定有效测点，也可只绑定授权楼栋。
- 任务发现：必须是任务指定执行角色，固定本任务、本测点、编辑时expectedRev；POST `/inspection/tasks/{id}/issues`。
- 独立上报POST `/issues`，source固定report，不附加预警eventId；source与位置由服务端重新校验。
- submissionId贯穿同一草稿；业务POST的Idempotency-Key在结果未知时保持不变，原始正文冻结。
- 任务问题与任务关联同事务；上报后不会把任务、问题、工单或预警全部标记完成。
- 任务上报后，返回清单保留填写；核对并采用当前任务版本、选择关联问题后再完成异常检查。
- 服务端复用独立上报回执前重新检查当前位置权限和有效档案；授权收回403、归档404。

## 照片处理

- 相册使用PhotoAccessHelper.PhotoViewPicker；相机使用cameraPicker，取消/拒绝/能力缺失有明确反馈。
- 选择器在途不触发普通页面隐藏清空流程；返回后核对当前身份、范围、epoch和位置，再接纳照片。
- 原生解码并按长边1600/1000/640逐级尝试压缩JPEG；单张最多200 KB，每次最多3张、合计600 KB。
- 原始选择对象与压缩字节只留在ReportSession/ReportDraft；ArkUI状态只持有预览URI、大小、来源和服务端状态，不能持有ArrayBuffer。
- 缓存位于App私有cache目录。切换身份、连接或明确放弃时释放本次已知预览文件。
- 不伪造拍摄时间、位置或真实现场来源。验收图片明确标识为模拟素材；相册选择不代表现场拍照。
- 上传使用原始JPEG字节和image/jpeg；不是JSON/base64或前端临时图片ID。
- POST `/media?fileName=&pointId=`带照片固定幂等键和X-Dataset-Epoch；无测点时省略pointId。
- 服务端在媒体写事务内检查已提供的epoch，包括流读取期间发生复位的竞态；冲突不保留媒体行/审计/临时文件。
- 兼容旧客户端：媒体接口未携带epoch的旧请求沿用原行为；本版App始终携带，未宣称已强制所有旧Web入口升级。
- 上传成功仍显示“已上传，待关联”；仅问题事务确认关联后显示“已提交”。压缩后上传文件是本次核验原件，不代表未压缩的拍摄原文件。

## 失败、回读与恢复

- 上传响应丢失：保留相同照片字节和媒体键，再上传会复用原媒体，不增加配额。
- 问题响应丢失：冻结正文与业务键，单独“用原请求核验并重试”，不重传已确认媒体。
- 409保留照片与描述；任务版本必须由用户核对并明确采用，不能自动改版本覆盖。
- 身份/范围/epoch变化或取消授权租约使草稿及受保护照片失效；每个关键await之后重新核验。
- 问题池读取真实issues，区分待审核、专业排查、待复查、观察中及已关闭，并展示服务端审核意见。
- Web详情使用同一附件/媒体ID，受保护下载内容必须与App上传压缩字节SHA一致。
- 已提交问题和附件可以从备份恢复并在API/App重启后读回；未提交草稿和未知请求仍仅在内存，不作为阶段9离线成果。
