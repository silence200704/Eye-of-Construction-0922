## 固定演示路径

1. 异常监测 → 预警 → 助手解释 → 证据与地图。
2. OpenHarmony App巡检 → 模拟读卡/人工到点 → 清单 → 照片上报 → Web审核。
3. 派工 → 手机接单完工 → Web 验收 → 复查。
4. 手机断网办理 → 联网补传 → 检查无重复。
5. 口语知识问答 → 上下文追问 → 依据与功能跳转。

第一条必须在App展示三类模拟监测、设备在线/电量、筛选、历史预警、确认和排查/措施登记，
并展示预警频次/类型分布/周月统计；不能只在Web演示。界面声光提示只作为模拟效果。
这些路径不代表已完成通知要求的南向传感采集与实体声光模块，差距保留在赛题对照表。

## 交付与范围

内部完整交付Web、API、OpenHarmony原生HAP/必要APP发布包、迁移工具、模拟数据基线、媒体、本地模型、索引、
Docker 离线镜像及操作说明。默认 Windows Docker 本机、局域网真机联调。
首版助手主要在Web展示；App覆盖赛题北向与现场业务。现有阈值仍为演示规则，不是国家鉴定标准。
正式评审材料为匿名DOCX、≤5分钟且≤100MB的MP4、讲解≤10分钟的PPT，按通知打RAR；海报为可选宣传物。
Python/JS/TS/Vue/ArkTS/.ets文件尽量≤450行，函数≤80行、参数≤5个，目录文件尽量≤8。
