# 筑瞳双端视觉与比赛传播设计规范

计划修订：2026-10-25。用户要求Web和鸿蒙App更亲切、更有图案与美感，适合比赛展示和宣传。
本轮Web卡片、背景和交互重构已实施，见[Web交互规范](web-interaction-system.md)与[交付核验](../handoff/reports/design/01-web-refresh.md)。
App原型、52组SVG/PNG与7套匿名模板已交付，见[App设计批次报告](../handoff/reports/design/03-app-prototypes-assets.md)。
新版矢量小瞳视觉复核、锁定SDK资源导入及原生可达性/性能仍待实测，7A整体尚未全部验收。
现按通知赛题3与[赛题对照](competition-scope.md)执行；App目标为OpenHarmony API≥12，硬件输入全部模拟。

## 核心方向：温暖的校园守护

将“建筑安全监测后台”表达为“有人陪伴的校园守护工具”：清晨校园、温暖纸感底色、
圆润的小瞳、楼栋/树木/窗格/路径图案，与清晰的业务状态并存。
允许丰富插画、轻层次和柔和渐变；装饰集中在欢迎区、引导、空态、完成反馈和宣传画面，
正文、照片证据、告警和高密度表格保留清楚的阅读区域。避免把所有页面做成同一种大插画卡片。

Web用于总览、分析和管理，App用于现场一步一步办理；同一品牌、状态与图案，按各自平台设计布局。
App优先遵循ArkUI原生控件、安全区、返回和窗口适配；Web保留键盘、表格效率与宽屏空间。

## 初始视觉 token（原型评审后冻结）

| 类别 | 候选规范 | 用途 |
| --- | --- | --- |
| 主色 | Web保留现有校园青 #0F6E7C；App按相同品牌语义映射 | 主要按钮、选中导航、品牌关联 |
| 辅色 | 晴空蓝 #397AC3 | 帮助、知识来源、次级数据分类 |
| 点缀 | 杏黄 #F2C66D、淡桃 #F3B9A6 | 装饰、小瞳配件、非告警背景图形 |
| 背景/表面 | Web暖白 #F3F6F2、卡片白 #FFFFFF、浅青/杏黄/晴空蓝装饰面 | 大面积阅读、卡片与分层背景 |
| 文字 | 深墨 #203A37、次文字 #52665F | 阅读、说明与数字，不用浅灰承担关键正文 |
| 告警 | 黄关注/橙介入/红紧急，沿用业务级别语义 | 图标+文字+颜色，不能换成品牌色或只靠色块 |
| 形状 | 8单位间距基线；卡片约16–24圆角，字段与按钮随平台规范 | 亲和但不将数据表格全改为药丸形 |
| 字体 | 中文系统字体优先，字号随平台与辅助功能缩放 | 不依赖外网字体；数字易比较，正文不做图片字 |
| 图形 | 统一圆润线条、校园几何形、适度剪纸层次 | 同一线宽体系、可导出多尺寸 |

颜色只是设计提案；每组前景/背景组合须实测对比度，正文目标≥4.5:1，大字和必要图形目标≥3:1。
告警色和数据色另建语义token，按实际底色校验。不得把警报红用作普通品牌装饰主色。
Web以px/rem、鸿蒙以vp/fp等平台单位实现；共享语义token，不强行共享具体渲染代码。

## 小瞳形象与图案资产

小瞳定位为“认真、温和的校园守护伙伴”，保留可识别的眼睛/守护意象，先评估现有形象后更新。
状态表情不能反转业务含义：等待/查询、找到依据、缺资料、待同步、操作成功、需要关注应可区分。
告警场景使用克制提醒，不用庆祝、搞笑表情或游戏积分弱化风险。

| 素材组 | 首批计划量 | 典型位置与验收 |
| --- | --- | --- |
| 小瞳 | 1套主形象+6状态 | 入口、帮助、空态、同步、完成；宽窄屏可读、无外网依赖 |
| 校园场景插画 | 4幅 | Web总览、App工作台、巡检、维修；统一透视和色彩 |
| 场景空态 | 6幅 | 暂无任务/无搜索结果/未下载/断网/API不可用/暂无照片；每幅配可执行下一步 |
| 可平铺图案 | 4套 | 窗格、楼栋轮廓、树叶、巡检路径；各有低对比背景版和宣传版 |
| 业务图标 | 首批16个，按页面缺口补充 | 点检、巡检、上报、工单、同步等；图标配文字，不以emoji拼图标 |
| 流程图形 | 3套 | 到点→检查→提交、上报→审核、接单→完工→验收→复查 |
| 品牌应用 | 应用图标、启动画面、报告/封面模板 | 鸿蒙图标按目标平台要求导出；启动等待不人为延长 |

每类均交付可编辑源文件和经目标平台验证的导出资源；图标/图案优先矢量，
插画可用原生绘制或本地位图，具体SVG能力、格式和分辨率在锁定SDK上验证。
使用素材清单记录ID、用途、版本、作者/来源、许可、是否AI辅助、导出格式、尺寸和SHA-256。
公共网页、比赛提交和离线包均不使用授权不明图片或依赖外网CDN；赛事要求AI披露时按规则申报。
装饰插画不得作为现场照片、监测证据或已实现界面的截图使用。

## 页面设计清单

| 页面/模块 | 设计重点 |
| --- | --- |
| Web校园总览 | 校园场景横幅+真实摘要；用楼栋/路径图案串起任务、异常、处理中事项；首屏有明确行动入口 |
| Web地图/3D/趋势 | 图面为主、选中对象卡明确；色彩、图例、时间与来源可读；装饰不挡测点或曲线 |
| Web预警中心 | “需要关注”优先，级别/状态/位置/责任/下一步清楚；风险区不堆庆祝图案 |
| Web巡检/问题/工单 | 更友好的任务卡、列表与进度时间线；重要表单分组，错误贴近字段 |
| Web小瞳 | 亲和形象、对话引导、对象选择卡、业务事实与知识引用分区；保留缺依据与历史快照标记 |
| Web报表/设置 | 清爽的报告封面、打印版、可读表格；身份切换和连接设置易找 |
| App工作台/监测/预警 | 小瞳与校园插画、今日任务/当前异常、三类模拟监测、设备状态、筛选和历史事件；不写死数字 |
| App处置/统计 | 原生确认/排查/措施表单、维护台账、频次/类型/周月图表；模拟来源与查询时间清楚 |
| App任务/到点 | 大触控区、楼栋图案、任务进度；用三步引导降低填写负担，扫码/读卡来源明确 |
| App上报/工单 | 照片网格、检查清单、固定主要按钮、回执卡、退回理由；键盘不遮提交和错误 |
| App同步/我的 | 本地已保存/待同步/服务器已确认分列；温和说明和明确重试，不用成功动画遮盖失败 |

每页需覆盖正常、加载、空态、错误、无权/失效、提交中、成功或冲突等适用状态。
文案使用“照片还没上传完成，请重试”“草稿已保存在这台设备”等具体话语；
不使用“系统安全一切正常”替代缺数据，也不强迫用户理解token/epoch等内部名词。

## 动效、可达性与性能

- 微反馈约150–250ms、页面过渡约250–350ms为原型初值；实际以鸿蒙原生和Web流畅实测为准。
- 小瞳眨眼、路径渐显和轻浮动仅用于低风险区域；支持减少动态效果，装饰不持续占用关键工作区。
- 不使用假进度条模拟上传/检索结果；成功反馈由真实回执触发，错误和冲突不得播放成功反馈。
- App关键触控区目标≥48vp；Web小屏≥44CSS px，保留合理间距；键盘焦点、读屏名称和返回行为完整。
- Web375/768/1280/1920px视口设计走查；App手机窄/宽窗口与平板/折叠展开预览，记录实际设备/窗口尺寸。
- 正文放大、鸿蒙系统字体缩放、安全区、系统返回/手势、Web缩放和滚动不能截断主要任务。
- 装饰图独立懒加载/按需解码；首屏只加载必要素材。登记资源体积、首屏/内存/长列表表现，
  不因“美工更丰富”取消性能门槛或加载真实业务之前强放开场动画。

## 比赛演示与宣传物料

统一主题文案提案：“筑瞳，陪你守护每一栋校园建筑”。最终文案结合赛规和实际能力确认。

1. 一张主视觉海报：校园场景+小瞳+核心价值+真实Web/鸿蒙App截图。
2. 三张场景海报：发现异常、现场巡检、闭环处理/离线补传；每张只讲一个可演示故事。
3. 一张双端业务协同图：App现场记录→共同后端→Web审核与追踪，准确标注能力边界。
4. 一套16:9答辩/录屏封面和9:16移动端宣传模板，另导出赛事要求的准确尺寸。
5. 正式评审MP4≤5分钟且≤100MB（目标4分30秒至4分50秒）；PPT讲解≤10分钟（目标8–9分钟）。
6. 可选60–90秒宣传短片和竖屏素材与评审版分开，不代替正式提交；正式DOCX按通知宋体小四、1.5倍行距。

阶段7A产出品牌/素材/模板和页面原型；阶段10在功能通过后制作真实录屏、截图、海报和视频成品；
阶段11复核许可、AI辅助披露、设备/系统信息、字幕、截图与交付版本一致。
预览渲染和真实截图分别标记；未完成的服务卡片、真实NFC、分布式能力不得出现在“已实现”宣传中。
三类正式材料必须匿名；UI、录屏通知栏、字幕/页眉、PPT备注与文档元数据均检查，不嵌入学校/团队/教师身份。
硬件、设备状态和声光效果为模拟，不用实物插画冒充已连接开发板或实拍证据。

## 评审方式

先交一版明确视觉方向和关键页面原型，再一次集中确认小瞳、色彩、图案密度与首页，随后扩展。
视觉确认不是功能验收；按阶段7A/8/9/10/11分别核验实际页面、交互与数据证据。
风格检索参考fronted-zonghe的扁平图形/可达性原则；配色、插画密度和平台实现按本项目约束单独设计，
不照搬检索中的红色主色、外网字体或其他平台组件库。
